# 遗迹守卫 · Ruin Watch（回合制巡逻推断）

在扫雷式遗迹探索的基础上演进为**回合制守卫巡逻**：守卫沿公开路线行动，暗处初始相位未知；玩家靠联合推断决定下一步。

## 运行

```bash
npm install
npm run dev        # 本地开发
npm run typecheck  # 类型检查
npm run build      # 生产构建
npx tsx scripts/logic-test.ts   # 无头逻辑测试（34 项断言）
```

Docker：`docker compose up --build`，访问 http://localhost:18225。

## 核心规则

### 回合制
- 点击石板、选择等待或道具只是**登记意图（pending）**，不推进回合；展开任何面板也不推进。
- 只有点「确认并推进 1 回合」才按 `TURN_SEQUENCE` 的固定次序结算，且一次确认只走一个回合。
- 确认后 `pending` 立即清空，重复点击确认不会多走回合或多结算发现（幂等）。

### 守卫与巡逻
- 每名守卫有一条**公开闭合路线**，每回合沿路线前进一格；路线互不重叠，任意回合都不可能共格（`advanceGuardPositions` 防御性校验）。
- 初始相位在暗处，推断模块只读取公开的 `track`，**永不读取 `phase` 或 `mine` 真相**。
- 脚步报告只给出各**区域的守卫数量**，不透露具体格；未被占据的区域显式记 0。

### 石板数字与证据
- 数字在观测回合冻结：`observedNumber = 固定陷阱数 + 观测时相邻守卫数`，并带 `observedAt` 回合标签；旧数字永久保留其回合。
- 探针只确认固定陷阱（不揭开），火把安全则揭开、陷阱则仅确认；结论与旗标都标注回合。旗标是玩家判断，**不进入推断证据**。
- 所有证据（脚步 `footsteps`、目击 `sightings`、石板 `slates`）都带回合，刷新后据此重建推断。

### 联合推断（`features/inference`）
- **联合枚举**所有守卫的相位组合并递归剪枝，而不是各自独立追踪后相乘——后者会保留不可能同时出现的位置。
- 用历轮脚步、目击、石板数字逐条淘汰；等价情形（当前相位相同 ⇒ 过去与未来位置完全一致）合并，累计权重但不丢未来移动信息。
- 每个幸存情形再求解固定陷阱 CSP（单位传播 + 回溯），不可行的情形被新公开事实淘汰。
- 下一步风险只依据幸存情形：**所有情形都安全**才把某格列入 `safeCells`；任一情形有守卫或陷阱可能都不给安全结论。

### 固定回合次序
1. 登记意图 → 2. 回合初观测（数字冻结）→ 3. 空区展开 → 4. 道具结算 → 5. 守卫移动 → 6. 遭遇结算 → 7. 脚步报告 → 8. 回合 +1。

守卫在移动**之后**踏入玩家本回合揭开的石板才造成伤害；固定陷阱在观测时即结算。守护符石可挡一次任意伤害，激活本身不推进回合。

## 存档

- 版本号 `version: 2`，localStorage key `ruinfield-jdk025-v2`。
- 加载时严格校验巡逻结构（闭合、不重复、不共格）、带回合证据与报告；旧版本或损坏存档不会覆盖，回退到新探险。
- 刷新恢复的记录足以重建与刷新前完全相同的联合情形集合。
